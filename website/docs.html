Chapter 01

Overview

CADSwarm is a shared FreeCAD workspace. Everyone on a team opens the same live model, and so do their AI helpers: Claude Code, Codex, OpenCode or another agent CLI you already use. A helper can build a part, and it appears in everyone's window a moment later, coloured by who made it. People watch, chat, steer, and can take over a part by hand when that's quicker than describing it.

There is no cloud account and no CADSwarm server. One person's computer hosts the team — the model file, the files the team saves, and a SpacetimeDB database that holds who is here, what is held, and what was said.

WhoWhat they do
PeopleJoin with an invite code, watch the model, message helpers, hand out work, edit parts by hand, run checks, export. Only a person can change team settings or delete snapshots and exports.
AI helpersBuild and change parts through a set of CAD tools, claim tasks, message each other, ask the helper holding a part to change it. They are always ordinary team members — never admins.
The host's computerRuns the team server: it applies every change to the real model.FCStd one at a time, serves files, and starts the planner, workers and reviewer for whole-team requests.

What's shared, what's local

  • Shared: the model (objects, revisions, locks), the Params sheet, tasks, chat, briefs, reviews, pointers, and the team's files and library — all through the team's database.
  • On the host's disk: the live model.FCStd, files/, exports/, snapshots/, library/ and the team's local knowledge and design memory.
  • On each person's disk: their AI helper's workspace and sign-in, under AI helpers\. Not shared, never uploaded.
How it fits together
people (FreeCAD panel, phone)  ─┐
                                ├─► SpacetimeDB: members · locks · revisions ·
AI helpers (Claude, Codex, …)  ─┘     tasks · chat · briefs · stale sweep
                                                   │
                                                   ▼
                                     host computer: cadswarm-host
                                     ├─ FreeCAD worker: the live model.FCStd
                                     └─ files · exports · snapshots · library

Why parts don't collide

  • Object locks. You can only change objects you hold, and anything you create is yours.
  • Transactional rollback. A change that touches an object you don't hold is aborted inside FreeCAD before anything is saved.
  • A shared Params sheet. Geometry binds to shared dimensions with FreeCAD expressions, so changing one size recomputes every dependent part and tells its owner.
  • Heartbeats and takeover. If a helper dies, its parts stay protected until a teammate takes over its locks and tasks (or ten minutes pass and they're released).
Where to go next

New to this? The quickstart walks one build end to end. The rest of this page is the reference you'll come back to.

Chapter 02

Install and update

CADSwarm is a FreeCAD workbench plus a small program that the installer puts in place. Installing it does not touch your FreeCAD settings or your documents.

What you need

RequirementDetails
FreeCAD 1.0 or newerFrom freecad.org. On Linux, use the official AppImage — snap, Flatpak and distro packages ship no Python, so with them you can join a team but not host one or run a helper.
An AI helperClaude Code, Codex, OpenCode, or any agent CLI you can point at a prompt. It must be signed in once on this computer. Each person connects their own; nobody shares an account.
A terminalOnly for the install line (and for signing the agent CLI in). After that, everything happens in FreeCAD.

Quick install

One line downloads CADSwarm, finds FreeCAD (offering to install it if it's missing), copies the workbench into place, offers a desktop shortcut, and opens FreeCAD with the setup guide.

Windows · PowerShell 
> irm https://raw.githubusercontent.com/SachchitBalamurugan/cadswarm/main/install/quick-install.ps1 | iex
macOS and Linux · Terminal 
$ curl -fsSL https://raw.githubusercontent.com/SachchitBalamurugan/cadswarm/main/install/quick-install.sh | bash

Install by hand

  1. Install FreeCAD 1.0+

    Default options are fine. On Linux, the official AppImage.

  2. Download CADSwarm

    On GitHub, Code ▸ Download ZIP, then unzip it anywhere.

  3. Run the installer

    Windows: Install CadSwarm.cmd. macOS: Install CadSwarm.command (right-click ▸ Open the first time). Linux: bash "Install CadSwarm.sh".

  4. Follow the guide in FreeCAD

    Start a new team project, or paste a teammate's invite code to join one.

What gets downloaded

DownloadWhenWhere
About 70 MB of helper softwareFirst installCADSwarm's app folder (%APPDATA%\CadSwarm on Windows, ~/Library/Application Support/CadSwarm on macOS, ~/.local/share/CadSwarm on Linux)
The team server and SpacetimeDB, about 50 MBFirst time you host a teamThe same app folder, each file checked by SHA-256
Official FreeCAD (Linux, optional)If you accept the offer and have no AppImageThe app folder, about 3 GB unpacked
Gmsh, onceFirst strength check (FEA) that needs itThe app folder's tools, pinned build and checksum; never into FreeCAD or the system

Nothing is installed into FreeCAD itself, and a team server or SpacetimeDB already on your PATH is used as it is.

Updating

Run the installer again — the same command, or the same file. It replaces the workbench with a clean copy and leaves your projects in Documents alone. Close FreeCAD first when the installer asks.

Two things update themselves: CADSwarm's app folder (the team server, SpacetimeDB and the database module are replaced when a release publishes a different file, checked by SHA-256) and any helper software it manages. If a team server is running while a new one lands, the old file is set aside and the update completes — no need to kill a process.

Restart FreeCAD after updating

FreeCAD loads the workbench once at start-up. An update shows up the next time you open it. Teams and hosts keep running through the update.

Uninstalling

Close FreeCAD, then delete the CadSwarm folder from FreeCAD's Mod directory (the one the installer printed, usually under %APPDATA%\FreeCAD\<version>\Mod) and the shortcut if you made one. Delete the app folder too if you want the downloaded tools gone. Your projects stay where they are; they're ordinary folders.

Chapter 03

Start a team

One person starts the team and becomes its host. Pick the computer that will stay on while people work: a desktop is a better host than a laptop that leaves the house.

The guide, step by step

  1. CADSwarm ▸ Get started…

    Also the first page you see after installing. Past projects are listed above the two buttons if this computer has joined any.

  2. Start a new team project

    Project name, your name, and where the project is saved.

  3. Choose where the database lives

    On this computer, or SpacetimeDB Maincloud.

  4. Create my team

    The first time, this downloads the team server and SpacetimeDB and publishes the team's database.

  5. Copy the invite code

    Then connect your own AI helper and finish.

Where the project lives

The default is Documents\CadSwarm\<project name>. If you pick a folder that already has other things in it, CADSwarm makes its own subfolder there, so nothing you already had is mixed in or overwritten. If the folder is already a CADSwarm project, you continue that one.

The folder is the project. Copy it and you've copied the work; open it with Get started ▸ Open a previous project… and CADSwarm rejoins the team it belongs to. What it can't do is move a team to another computer for you — a local team's database lives in the host's app data, so keep the folder with the host.

Local or Maincloud?

On this computer (default)SpacetimeDB Maincloud
AccountNoneFree SpacetimeDB sign-in, once, in your browser
Who can joinPeople on the same network as the hostAnyone with an invite, anywhere
Works offlineYes, on the local networkNo
EncryptionNo TLS — use it with people you trust on your own networkTLS handled by SpacetimeDB
The model still livesOn the hostOn the host

Either way the database only holds state — members, locks, tasks, chat. The model and files stay on the host's computer, and only the host writes them.

Windows firewall

The first time you host a local team, Windows may ask whether to allow CADSwarm through the firewall. Allow it on private networks, or teammates can't reach the team.

Invite codes

  • One code per person or helper, each single-use and valid for one day.
  • Make one from the guide's invite page, or any time from Tools ▸ AI helpers ▸ Invite a teammate….
  • Codes carry the database address, so a teammate needs nothing else. They can be pasted as text, as a bare ticket, or opened as a phone link.
  • Lost one? Make another. An unused code simply expires.

Hosting duties

  • Keep the computer on while the team works. The host program keeps running even if you close FreeCAD, but not through a reboot.
  • Start it again after a reboot by opening CADSwarm — the guide offers to restart the team's server, and the team's session picks up where it was.
  • Watch disk space. Exports, snapshots and file versions live on your disk; the panel shows what's using it (see Files and storage).
  • Stop hosting from Tools ▸ Stop hosting the team or CADSwarm ▸ Stop hosting. That ends the session for everyone until it's started again; nothing is deleted.
If the host goes offline

Teammates can still see the team's state — who's here, tasks, chat — but the model stops changing and files can't be saved until the host is back. That's the trade for your designs staying on your machines.

Chapter 04

Join a team

Joining is the short path: install CADSwarm, paste a code, connect your helper.

  1. Install CADSwarm

    Same installer as the host. Only the host downloads the team server.

  2. Get started ▸ Join a teammate's project

    Paste the invite code. It's checked, then used up.

  3. Connect your AI helper

    Pick the CLI you use and give it a name. It joins as a member of the team, running on your computer.

  4. That's it

    The live model opens in its own read-only tab, and the panel shows the team.

What you can do as a member

Everything except the host-only actions: you can add parts, edit parts by hand, run checks, save files, export, invite people (if you have a code to give) and message helpers. Stop hosting, Open project folder and the storage dialog belong to the host, because those are the host's computer and disk.

Coming back later

Your sign-in is kept per team on this computer, so reopening the project needs no new code: pick it from CADSwarm ▸ Get started ▸ Open a previous project…, or from the list on the guide's first page. To leave deliberately, use CADSwarm ▸ Leave team — that releases the parts you hold.

Same network

On a team hosted on someone's computer, you must be on the same network as the host. Maincloud teams work from anywhere.

Chapter 05

The panel

The CADSwarm Team panel is a dock on the right of the FreeCAD window. Drag its edge to give it more or less room; it scrolls when the window is short. The title shows the team and project, with the connection state beside it.

TabWhat's in it
TeamEveryone here: each helper's name, the task it's on (or next: …), its status, and the parts it holds. People are listed underneath. Suggestions from helpers wait at the top.
ChatOne box for everything: tasks for helpers, requests for the whole team, and talk between people. See Talking to helpers.
TasksOpen work, whole-team requests with their parts underneath, and what the reviewer found. Start it, I'll do it, Mark done.
ActivityWhat happened, in order: parts added, tasks finished, files saved, renames, clashes, and the 🤝 messages helpers send each other.
SizesThe team's shared dimensions, editable in place. See Shared sizes.
FilesNotes, plans, BOMs and scripts the team saved, with version, author and time. See Files and storage.
LibraryThe team's parts shelf: your own parts and the standard screws, bearings and inserts. See Parts library.
RemoteA single-use code and QR for a phone. See Phone and browser.
ToolsEverything else, in groups: Build, Print, Project, Team rules, AI helpers, Parts, 3D view, and Stop hosting the team. The full list is in Menu and panel.

Reading the Team tab

  • The dot is the helper's colour — the same colour its parts get in the 3D view, so you can tell at a glance who built what.
  • Ready means it's listening. ◐ Working means it's mid-task. A quiet helper shows how long it's been silent instead.
  • Holding lists the parts only that helper can change right now.
  • Right-click one of your own helpers to Rename, Restart or see its log. Right-click any helper, including one on a teammate's computer, to Remove from the team.

The 3D view

  • Show helpers' arrows puts an arrow in each helper's colour on the part it's working on. Preview opens a demo model so you can see what that looks like before a real build.
  • The live model opens in its own tab named after the project, with (live, read-only) in the title where the guide adds it. Refreshes, new parts and reconnects never switch you away from your own document; only the guide's Done, show me the model brings it forward.
Chapter 06

Talking to helpers

One box does everything. What you type decides where it goes:

You typeWhat happens
@sam-claude …A task for that helper, with the parts you have selected attached. It wakes, answers with what it will do, then what it did.
@a @b …The same task for each named helper.
@team …A whole-team request: the host plans it into parts, starts helpers for them, reviews the result and exports once. The chat notes where it went; that note is local to your window.
@all …A note to every helper (pause, status, a house rule). Not a task.
No @Chat between people. Helpers never see it.

Typing @ alone lists the names you can use. Tasks only go to helpers: people pick their own work from the Tasks tab.

Did it land?

Your message carries its own state: ⏳ not read yet, 👀 read, working on it, ✓ done. If a helper is what's missing, the panel says how long it has been quiet, and its log is one right-click away.

Commands come first

A person's instruction is a command, not chat: it sits at the top of the helper's inbox and is never treated as one request among many. The sender sees sent → seen → done. Requests between helpers are requests, never permissions — a helper can't let another helper change a part it holds.

Whole-team requests

@team hands the job to the team server, which:

  1. plans the request into parts and tasks,
  2. starts AI helpers for those tasks on the host's computer,
  3. wakes the helpers as work becomes available,
  4. starts the team's reviewer when every task is done,
  5. exports the result once, to exports/.

A failed start is retried a few times with a growing pause, then the brief fails with the tail of the agent's log in the panel — instead of retrying forever. If the reviewer finds something, the owners are woken to fix it and the reviewer runs again.

Planners, workers and the reviewer are one-job helpers: each leaves the team as soon as its run ends, so a finished or failed request does not leave a row of idle "workers" behind. When the request is over the host also removes the folder each start used under agents\. A worker that stopped with its task still open gives it back, and one whose MCP server went quiet is taken off the team too, so a task never waits as "needs someone" — a fresh worker picks it up.

Asking well

  • Say what and how big. "A 120 × 80 × 6 mm plate, 3 mm chamfer, four M3 holes on a 100 × 60 grid" beats "a plate".
  • Select first when it's about a part. Selecting a part and then typing @helper make this 10 mm shorter is unambiguous.
  • One change at a time. Corrections land faster than a paragraph of new requirements.
  • Ask for the check. "Then check it fits the printer" is a sentence the helper can act on.
Chapter 07

Edit a part yourself

Sometimes moving a hole two millimetres is faster than describing it. You don't need to be a CAD user for this.

  1. Select the part

    In the live model's 3D view.

  2. Tools ▸ ✎ Edit a part yourself…

    The editor opens on the part. While it's open the part is held by you, so no helper can change it underneath you.

  3. Change it

    Type a new size or position, or move it with FreeCAD's own Edit ▸ Placement / Transform — the editor picks the move up.

  4. Save to team

    One change, sent to everyone. Done just releases the part.

  • Held by a helper? The editor offers Ask … to let go, and Free it anyway if that helper has gone quiet.
  • Moving without the editor is undone with an explanation, so your view never silently differs from the team's.
  • Handing over: while you hold a part, Hand off now with a note starts a helper that takes your locks and tasks and carries on from your note and recent changes.
  • Limits: sizes of primitives (box, cylinder, sphere, cone, torus) and position/rotation of any part. Sketch-based or fused parts can be moved but not reshaped by hand — ask a helper for those.
Chapter 08

Shared sizes and precision

Every project has a Params spreadsheet. Helpers bind geometry to it with FreeCAD expressions, so a dimension lives in one place instead of being retyped in twenty parts.

Changing a shared size

  • Use the Sizes tab, or Tools ▸ Change a shared size….
  • Every part that reads the value recomputes. If that part belongs to someone else, its revision goes up and its owner is told.
  • Values you'd expect are there already: wall thickness, hole pitches, fits, and anything the team settled on.

Auto-constrain looks at the model for sizes and fits it already repeats and offers to bind them to shared sizes — a good first tidy-up when a project has grown organically.

Precision settings

One dialog for the whole team (Tools ▸ Team rules ▸ Precision settings…):

GroupWhat it holds
Fits and clearancesGeneral clearance, slip fit and press fit — also shared sizes (Params.tol_clearance, Params.tol_press_fit, …), so geometry bound to them moves when they change.
Bolt holesISO 273 class: close, normal or loose.
Screws in printed partsHeat-set inserts, tapped, or self-tapping — what the helper should size a hole for.
PrintingXY compensation, thinnest wall, layer height.
MeshPrecision for STL exports and previews.
Clash checkThe smallest overlap worth reporting.
Part editorDecimals shown, and the arrow-key step.

Only people change settings. When a part implies a different value — a press-fit bearing seat, holes so small a coarse mesh would facet them — a helper suggests it with a reason. The suggestion waits at the top of the Team tab and in Settings for someone to Accept or Dismiss.

Chapter 09

Files, exports and storage

The project folder is the whole project. It grows into subfolders as the team works:

Project folder
Phone stand/
  model.FCStd          the live shared model (only the team server writes it)
  files/               notes, plans, BOMs and scripts, in subfolders that grow
    parts/base/notes.md
    docs/bom.csv
    fea/2026-10-23 21.05 shelf bracket/   report.html · report.json · plot.png
    lattice/           lightened parts and their reports
  exports/             STEP and STL files, each with a new name
  snapshots/           saved versions of the model
  library/             the team's parts, one folder per part
  AI helpers/          each helper's workspace on this computer (not shared)
  .cadswarm-team/      the team server's data and design memory
  README.txt           explains the above to anyone browsing the folder

Save safety

The team server enforces these rules; helpers can't opt out of them:

  • Sandboxed to files/. Paths with .., absolute paths, hidden or reserved names, and links pointing outside are refused. File types are on an allow-list.
  • No silent overwrites. Saving onto an existing file is refused unless the helper asks for a new name or for replace with the version it last read. If anyone changed it since — including a person editing it by hand — the save is refused.
  • History. Replaced, moved and deleted files keep their last 20 versions (and everything from the last day) and can be restored. A deleted file always keeps its latest version.
  • Atomic writes. A crash never leaves half a file.

Limits: 5 MB per text file (notes, scripts, CSV), 512 MB per binary CAD or media file (STEP, STL, 3MF, FCStd, DXF, PDF, images).

Finding what the team saved

The Files tab lists everything with its version, who saved it and when, and saves a copy wherever you like. The host also gets Tools ▸ Project ▸ Open project folder.

Exports and snapshots

  • Save as STL/STEP file… writes into exports/. A second export gets a new name; nothing is overwritten or auto-deleted.
  • Save a snapshot… keeps a version of the model, named with the date, time and your label. Snapshots are never deleted automatically.

Disk space

GuardDefault
Free space left on the host's driveNever below 2 GB (or 10% of the drive, if that's smaller). The save is refused with a plain reason instead of filling the disk.
Project limit20 GB across files, history, snapshots and exports. Set by the host in Tools ▸ Project ▸ Storage and free up space…, or with CADSWARM_PROJECT_LIMIT_GB. 0 means no project limit.
History kept20 versions per file, plus everything from the last day. Change it in the same dialog.

Storage and free up space shows what is using the room and lets a person trim old versions, old snapshots (always keeping the newest few) and old exports. Helpers can look, and are told to ask a person — they can't delete.

Chapter 10

Checks and reports

Four kinds of check, all reachable from the panel and all usable without a helper.

Clashes

Tools ▸ Build ▸ Check for clashes finds parts that overlap and lists them. The smallest overlap worth reporting is a precision setting. Helpers can run the same check with check_interference.

Will it print?

Tell the team what you print on once (Tools ▸ Print ▸ Printer bed…), then Check it fits the printer… checks three things: every part fits the bed, the solids are closed, and walls are thick enough to print (under 1.2 mm is flagged).

Strength checks (FEA)

Ask in the chat: “will this bracket hold 10 kg?”, “what's the natural frequency of the arm?”, “how hot does the motor mount get?”. The helper recognises a simulation request and asks, in one message, which analysis to run — linear static (stress, deflection, safety factor), modal or steady-state thermal — plus the material, the faces held still and the loads.

If you don't know, it uses clearly marked placeholders (generic steel, a 1000 N load on the top face, the bottom face fixed) and the report says so in a yellow box. The analysis runs FreeCAD's own FEM tools on a copy of the part, in a separate process, so the model, its locks and everyone else's work are untouched.

  • Where it goes: files/fea/, as a self-contained HTML page plus JSON.
  • Who sees it: the report pops up in every teammate's FreeCAD. Tools ▸ Project ▸ Simulation reports… lists the past ones.
  • What's in it: the numbers, the automatic checks (safety factor, stress peaks at supports or sharp corners, coarse mesh, resonance, temperature limits, placeholders) and the helper's own plain-words summary and suggestions.
  • If a helper forgets to publish: the host publishes the automatic checks after five minutes.
  • Gmsh: if this FreeCAD has no Gmsh, the host installs the official 4.15.2 build once into the app folder. CADSWARM_NO_AUTO_INSTALL=1 turns that off.
Read it as a design aid

Linear-elastic behaviour with idealised supports is a guide, not a certification. Check anything load-bearing yourself.

Lighten a part

Tools ▸ Build ▸ Lighten part… fills a part with a lattice that is thicker where the stress is high, keeps a solid skin and solid zones where the part is held and loaded, then simulates the real lattice to check it still has the stiffness you asked for (90% by default).

Pick the faces it's held by and loaded on, the material and how it's made. You get the weight saving, the verified stiffness, a preview you can cut open, and STL, 3MF and a report in files/lattice/. Add to model puts the lattice next to the original as a mesh — the original is never changed. Helpers use lighten_part and suggest it when a part could be lighter, including when a strength check shows room to spare.

Optimize Part

For simulation-guided material removal from supported, grid-aligned solids, the workbench also includes Optimize Part…. It preserves the original and shares a new part only after you accept it. The method and its limits are written up in the repository: structural optimization.

The team's reviewer

Every @team request ends with one more helper started as the reviewer. It checks collisions between parts, that the board actually fits (dimensions, mounting holes, port cutouts), printability (bed size, closed solids, thin walls) and the team's learned rules. It is read-only by construction: the database refuses every write from a reviewer, so it cannot change geometry even by accident.

Its tool calls and findings appear in Activity, its verdict lands as a review card on the request, and its arrow parks on the part it's checking. If it can't start three times in a row, the request fails with the tail of its log instead of retrying forever.

Chapter 11

Parts library

The team's parts shelf, in the Library tab (and in the browser app). It's for the things you shouldn't be modelling by hand: screws, bearings, inserts, and parts someone already downloaded.

WhatHow
Your team's partsUpload a part… takes a STEP, FreeCAD or STL file. Add from a link… takes a direct download link from a vendor or a repository. FreeCAD measures each one (size, volume, holes) and makes a preview. The files live in the project's library/.
Standard partsBuilt to their real dimensions: socket and button head screws (ISO 4762 / 7380), hex nuts, washers, heat-set inserts, ball bearings (608 and friends), dowel pins and disc magnets.
Placing onePlace in model puts it in the shared model, held by you, and offers to position it.
Choosing oneWhich part should I use? describes a need (“an 8 mm axle that spins”) and suggests parts, each with the hole the mating part needs.
Sharing a shelfMore ▾ › Export the library as a pack… saves the team's parts and settings as a zip in the project files; Import a pack… brings them into another project. Imported settings arrive as suggestions only.

Helpers use the same shelf: they check it before modelling a screw or a bearing (recommend_components, search_components), place parts (add_standard_part, insert_component), size mating holes with the team's fits (hole_size), and can add a part they found online with its license (import_component_from_url).

Chapter 12

Phone and browser

You don't need FreeCAD to watch a build or answer a helper. The Remote tab mints one single-use code and shows it as a QR plus a link.

  1. Open the Remote tab

    In the CADSwarm panel, on the host or any member's window.

  2. Scan the QR

    Or send the link. The phone opens the build in its browser.

  3. Make another with New code

    Each code works once, and only while the host's team server is running.

The browser app has tabs for Chat, Model, Sizes, Library, Tasks, Files and Team. You can watch the model, follow the chat, send @ commands, read tasks and files, and answer a suggestion — the same session, from the sofa.

Two limits worth knowing

A phone link points at https://cadswarm.design/app unless the host was started with its own web address. And a phone reaching the app through the public site can't reach a team hosted on a computer on your home network — for those, watch from FreeCAD on a computer that's on the same network.

Chapter 13

AI helpers

A helper is an agent CLI (Claude Code, Codex, OpenCode, or your own) joined to the team, running on one person's computer with that person's account. It gets a set of CAD tools and a workspace of its own under the project's AI helpers\ folder.

Adding, naming, managing

  • New helper in the Team tab, or Tools ▸ AI helpers ▸ Set up a helper step by step… (also CADSwarm ▸ Add AI helper…). Pick the CLI, optionally a name; the default is your name and the AI, like carol-claude.
  • Rename, Restart and Show log are on the right-click menu for helpers on your computer.
  • Remove from the team works on any helper, even one on a teammate's computer. Removing releases its locks, returns the work it held, and stops it rejoining on its own — only a fresh invite brings it back.
  • Helpers always join as ordinary members. They can't change settings, delete snapshots or exports, or write outside the project's files/.

When does a helper wake?

  • A message or task addressed to it wakes it. Your instruction is a command and comes first in its inbox.
  • When a task it handed to another helper finishes, it's woken with the result.
  • Each helper runs at most 30 times an hour, so two helpers can't keep waking each other in a loop.
  • A helper that hasn't checked in for 30 seconds shows as quiet. Its parts stay held, its tasks become awaiting takeover, and anyone can take over its work. After ten minutes the locks are freed and the tasks reopen.

Helpers working together

A helper can see who is free (list_helpers), hand part of a job to another helper (delegate_task, which wakes it), and ask whoever holds a part to change it. A request is a request: it never grants permission to change something another helper holds.

Which CLI runs what

  • Your helper runs whichever CLI you connected, on your computer.
  • Planners, workers and the reviewer for @team requests run on the host's computer with the host's CLI. The host picks it when setting up the team; an unsupported CLI can be wired in with agent_command in the project's host.json, where {prompt} is replaced by the task.
  • A CLI that isn't on PATH can be pointed at with CADSWARM_CLAUDE, CADSWARM_CODEX or CADSWARM_OPENCODE.

Scripts run apart from the model

When a helper runs run_part_script, CADSwarm starts a separate, throw-away FreeCAD process — never the live model's own. The script works on a read-only copy and can hand back a shape and some data; anything else it does to the copy is discarded, so it can't change other people's parts.

How tightly that process is locked down depends on your computer (the model server's /health shows the level under script_sandbox):

LevelWhat it means
appcontainer (Windows 10/11)No network, no access to your documents or profile, can't start other programs, writes only to a scratch folder that's deleted afterwards. About 2 GB of memory and 60 seconds. The first start gives the container read access to your FreeCAD folder, which can take a few seconds.
lowintegrity (Windows fallback)Still can't write outside the scratch folder or start programs, but can read your files and use the network. Use it with people you trust.
process-limits (macOS, Linux)Memory, time and open-file limits, but no file or network isolation — it runs as you. Use it with people you trust.

Settings: CADSWARM_SCRIPT_TIMEOUT (seconds) and CADSWARM_SCRIPT_MEMORY_MB. CADSWARM_SCRIPT_SANDBOX=off disables the sandbox for debugging and prints a loud warning. Whatever the level, the sandbox protects your files and network, not the model: a script can return any shape, so review what a teammate's helper adds.

Context on every prompt

Claude Code and Codex get a hook that adds a team block before each prompt: who holds which parts, open tasks, what changed since your last prompt, unread messages. It fails open — if the database is unreachable, the prompt goes through without it. OpenCode gets the same information through the tools instead. Codex only uses hooks you have trusted: type /hooks in Codex and trust the CADSwarm hook (again after an update, since Codex re-checks it when it changes).

When a helper misbehaves

Right-click ▸ Show log (or Tools ▸ AI helpers ▸ Show my AI helpers' logs) shows what it actually wrote. The two usual causes are a CLI that never finished signing in, and a run limit — the panel shows how long a helper has been quiet, and Restart starts a fresh process without losing its workspace.

Chapter 14

Learned design style

CADSwarm learns how your team designs and teaches it to every helper. The host notes each change to the model — who made it, whether a person or a helper, and what changed — plus every finished request. From that it works out rules:

  • Shared sizes the team settles on — “Params.wall is 2.4 mm”.
  • What people keep correcting after a helper. The strongest signal, so it counts double.
  • Preferred parts — “M3 heat-set inserts”.
  • Modelling habits — binding sizes to Params.
  • Problems reviews keep finding for a board.

A rule with enough consistent, recent evidence from more than one person or day becomes active: planners, workers, handed-off helpers and the reviewer get it in their prompts, and every helper turn shows it as “Team design style”.

Weaker rules, and rules a helper proposes, wait for a person. The Team tab shows one summary line and a Review button; it opens the triage inbox under Tools ▸ Team rules ▸ Learned design style…. Rules that describe the same thing are one decision — a shared size and the corrections people keep making to it are answered together — grouped by kind, each with a Ready, Look or Weak badge worked out from its evidence. Make the ready rules and Dismiss the weak ones answer a whole set in one visible action; each lists the exact statements first, all selected, and any can be unticked. Every section also has Use all / Dismiss all.

Kind of ruleWhat happens
Suggested (weak, or proposed by a helper)One decision per thing learned, with a Ready / Look / Weak badge. Answer it with Make it a rule or Dismiss, or use a section's or the ready set's bulk action.
ConfirmedAlways followed, never fades. You can also type one yourself; it's confirmed at once.
DismissedStays away until its evidence doubles.
Undecided and weakLeaves the inbox after two weeks without new evidence. It waits under Expired or dismissed, where Make it a rule brings it back; doubling evidence revives it on its own too.
Unused and learnedStops guiding helpers when its evidence goes stale, then expires from the inbox.

Rules live in the project database on the host's computer. Learning needs no account, keys or network. python -m cadswarm.style_memory show --project <folder> prints them from a terminal.

Chapter 15

Troubleshooting

Before anything else, check three things: the host's computer is on and CADSwarm is open there, you're on the same network (local teams only), and your agent CLI is signed in on this computer.

What you seeWhat it meansWhat to do
“Couldn't reach your team's server at …”Nothing answered at that address.Start CADSwarm on the host. On a local team, check the network and the host's firewall. If the host's address changed, ask for a new invite.
“That project's database isn't on this computer's team server any more”The team's database was rebuilt from empty — the id in your saved sign-in no longer exists (404).Start the team again from Get started. The model file and files/ are still in the project folder.
“That project's database is paused on SpacetimeDB”A Maincloud database that isn't running (503).Open it on spacetimedb.com, click Start Database, reconnect. Or host a new team on this computer.
“That invite code has already been used or has expired”Codes are single-use and last a day.Ask for a fresh one (Tools ▸ AI helpers ▸ Invite a teammate…).
“Your saved sign-in isn't part of this team any more”You were removed, or the team was rebuilt.Join again with a new invite.
“A teammate took over your session, so you were signed out”The same sign-in is open in another FreeCAD window.Join again in the window you want to keep.
Panel says ReconnectingThe host's team server stopped.It starts again when the host opens CADSwarm. Nothing is lost; the model simply pauses.
A helper never answersNot signed in, out of runs, or its CLI failed to start.Open its log. Sign the CLI in once in a terminal. Codex: /hooks ▸ trust. Then Restart.
Helpers can't be added at allA CLI CADSwarm can't find, or a Linux package without Python.Run claude / codex / opencode once in a terminal; on Linux switch to the official AppImage.
A save is refused: disk_fullThe host's drive would drop below the 2 GB guard, or the project is at its limit.Use Tools ▸ Project ▸ Storage and free up space… on the host, or raise the limit.
“This part is held by …”Someone (or their helper) holds it.Message the owner, use Ask … to let go, or Free it anyway when that helper has gone quiet.
Your move in the 3D view was undoneHand moves outside the editor aren't shared with the team.Use Tools ▸ ✎ Edit a part yourself….
The live model tab is read-onlyBy design: you edit through the panel, or through the part editor which takes a lock for you.Select a part and use the editor, or ask a helper.
FreeCAD doesn't show CADSwarmThe workbench isn't installed, or FreeCAD was open during install.Re-run the installer with FreeCAD closed, then reopen FreeCAD and pick CADSwarm.
The installer says a file is in use / “Couldn't put cadswarm-host.exe in place”An old team server is running from the same file.Update CADSwarm again — the installer sets the running file aside and finishes. If it persists, stop hosting (Tools ▸ Stop hosting the team) and retry.

Where to look when the table doesn't cover it

  • Activity — the last thing that happened, including refused changes and why.
  • A helper's log — right-click it, or Tools ▸ AI helpers ▸ Show my AI helpers' logs. The tail of that log is what a failed request shows in the panel.
  • FreeCAD's console — View ▸ Panels ▸ Report view. CADSwarm writes plain-words lines there, prefixed [CADSwarm].
  • The model server's /health — on the host, shows whether it's ready and which script sandbox level is active (script_sandbox).
Start over safely

If a team's state is beyond repair, the project folder is still worth keeping: model.FCStd, files/, exports/ and snapshots/ are ordinary files. Start a new team and bring the model in as a part, or keep working in the old folder with a fresh database.

Chapter 16

Limits and questions

Questions people ask first

QuestionAnswer
Do I need an account?No CADSwarm account. Only a Maincloud-hosted team needs a free SpacetimeDB sign-in, done once in the browser.
What does it cost?CADSwarm is free and open source. You bring your own AI subscription and your own FreeCAD.
Where does my model go?Onto the host's disk, and the team's database (state only). Nothing is uploaded to CADSwarm; there is no CADSwarm server.
Can I work offline?On a team hosted on your own network, yes. Maincloud teams need the internet.
Do I need to know CAD or code?No. Describing parts in chat is the main way; the part editor covers the small changes.
Which AI helpers work?Claude Code, Codex, OpenCode, or another CLI wired in with agent_command. Each person uses their own account.
Can a helper read my other files?Its workspace is inside the project. Scripts it runs are sandboxed (strictly on Windows, less so on macOS/Linux — see the table in AI helpers). Model helpers can only save through save_file, inside files/.
What if the host's laptop sleeps?Everyone's model pauses until it's back. The team's state stays readable, but nothing changes and nothing saves.
Can two teams be open at once?One session per FreeCAD window. Open another project from Get started ▸ Open a previous project…; the current session ends first.
Does it work with FreeCAD 1.1?Yes — 1.0 and newer. The workbench installs into whichever FreeCAD the installer finds.

Known limits

  • Hand edits are limited. Sizes of primitives and position/rotation of any part. Sketch-based or fused parts can be moved but not reshaped by hand.
  • Locks are per object. Editing a shared upstream object (say a sketch two features use) needs its lock; there's no sub-object locking.
  • One host, one worker. Each host drives a single FreeCAD worker, so changes apply one at a time. Helpers work in parallel; their edits queue.
  • The host must stay on. It serves the model, files, exports and snapshots.
  • Local teams have no TLS. Use them with people you trust on your own network; Maincloud handles TLS and sign-in.
  • A script's shape is trusted. The sandbox protects your files and network, not the model. Review what teammates' helpers add.
  • Phone links point at the public site. A team hosted locally is reachable from FreeCAD on the same network, not from a phone over the internet.
